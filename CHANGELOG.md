# Changelog

Версии — по тегам `vX.Y.Z`. Релиз на GitHub собирается из раздела этого файла автоматически, Docker-образ с тем же тегом публикуется в GHCR.

## 2.3.0 — 2026-10-29
**Исправлено**
- **`STAMP_MODE=on_geo_change`: панель теперь сверяется каждый цикл.** Раньше, пока гео-база не менялась, панель вообще не трогалась — поэтому новый клиент (например, FixErrorVPN после обновления до 2.2.0), новое правило или стёртый вручную заголовок ждали следующего обновления базы, до суток. Теперь недостающее дописывается сразу, с прежней меткой `LastUpdated`: клиенты ничего не перекачивают. Если всё совпадает — `PATCH` не отправляется.

**Добавлено**
- **`HAPP_EXTRA_RULES`** — полные имена других правил через запятую, в которые тоже пишется `routing` Happ, например общее `Xray` для всех Xray-клиентов. Имя сравнивается целиком, поэтому `Xray` не задевает `FixErrorVPN Xray`. Такие правила только обновляются, не создаются; правила Happ это не заменяет — если его нет, оно создаётся как раньше.

**При обновлении**
- Если `STAMP_MODE=on_geo_change` и метку в панели меняли вручную (например, разовым запуском в режиме `interval`), на первом цикле заголовки вернутся к метке из состояния сервиса — клиенты один раз перекачают базы.

## 2.2.0 — 2026-10-29
**Третий клиент — Windows-приложение FixErrorVPN.**
- В правила ответа FixErrorVPN пишутся `routing` = `fixerrorvpn://routing/onadd/<Base64>` (та же строка, что уходит Happ) и `autorouting` = `fixerrorvpn://autorouting/onadd/<AUTOROUTING_URL>` (тот же `routing.json`, что для INCY). Без `AUTOROUTING_URL` — только `routing`, оставшийся `autorouting` удаляется.
- Правила ищутся по имени: подстрока `fixerrorvpn` без учёта регистра (`FIXERRORVPN_RULE_MATCH`). Обновляются все совпавшие, например `FixErrorVPN Xray` и `FixErrorVPN Mihomo`.
- **Правила FixErrorVPN не создаются автоматически** — даже при `CREATE_MISSING_RULES=true`: у них условия по User-Agent приложения, их настраивает владелец панели. Правила нет — предупреждение в журнале.
- Хэдеры самого приложения (`fixerror-logo`, `fixerror-color`, `fixerror-buttons` и прочие), порядок правил, условия, `responseType` и `enabled` не меняются.
- Новые переменные: `ENABLE_FIXERRORVPN` (по умолчанию `true`), `FIXERRORVPN_RULE_MATCH` (по умолчанию `fixerrorvpn`).

**Обновлено**
- Базовый образ Docker: `python:3.15-alpine` (было `3.12-alpine`). CI проверяет код на Python 3.12 и 3.15.
- GitHub Actions: `actions/setup-python` v7.

**При обновлении**
- Если правил FixErrorVPN в панели нет и приложение не используется — пропишите `ENABLE_FIXERRORVPN=false`, иначе каждый цикл будет предупреждение.

## 2.1.0 — 2026-09-03
**Поддержка Remnawave 3.x.** Один образ работает и на 2.x, и на 3.x — версия определяется автоматически. Happ и INCY обрабатываются одинаково: роутинг доставляется только через заголовки в **Правилах ответов**. Поле `happRouting` (удалено в 3.0.0) больше не пишется.

**При обновлении**
- **Панель 2.x — очистите поле `Happ Routing`** в настройках подписки: оно перезаписывает заголовок из правила, и роутинг Happ замрёт на старом значении. Либо один раз запустите с `CLEAR_LEGACY_HAPP_ROUTING=true`.
- **`ENABLE_INCY` теперь `true` по умолчанию.** Не нужен — пропишите `false` явно.
- **Панель 3.x — включите сжатие на reverse proxy** (`encode` в Caddy, `gzip on;` в Nginx): панель больше не сжимает ответы сама.

**Исправлено**
- Автосозданное правило не срабатывало: оно добавлялось в конец списка, ниже правила `Fallback Base64` без условий. Теперь вставляется над первым таким правилом.
- Панель без правил (`responseRules: null`) роняла сервис.

**Добавлено**
- Созданное правило наследует `responseType` правила по умолчанию — формат подписки у клиентов не меняется.
- Проверка `AUTOROUTING_URL` на первом цикле: сервис сам скачивает ссылку и пишет в журнал, отдаёт ли прокси актуальный `routing.json`.
- `PATCH` отправляет только изменения, а не все настройки.
- Новые переменные: `PANEL_VERSION`, `CREATE_MISSING_RULES`, `HAPP_RESPONSE_TYPE`, `HAPP_RULE_MATCH`, `INCY_RULE_MATCH`, `CLEAR_LEGACY_HAPP_ROUTING`.

## 2.0.0 — 2026-07-11
Из простого «обновлятеля метки» сервис стал полноценным менеджером роутинга.
- **Своё зеркало гео-баз** (`GEO_MIRROR_ENABLED`) — `geoip.dat` / `geosite.dat` со своего домена там, где GitHub заблокирован; условные запросы `304` и атомарная запись.
- **Обрезка баз на сервере** (`GEO_TRIM_ENABLED`) — только категории из шаблона: файлы ~10–17 МБ превращаются в сотни КБ.
- **Умная метка** (`STAMP_MODE=on_geo_change`) — `LastUpdated` меняется, только когда база действительно изменилась.
- Автосоздание правила для INCY.
- Модульный пакет `routing_updater`, тесты `pytest`, CI (`ruff` + тесты), повторы при сетевых ошибках, корректная остановка.
- Примеры reverse proxy для Nginx / Angie, Caddy и Traefik.
- Готовый образ в GitHub Container Registry — клонировать и собирать не нужно.
